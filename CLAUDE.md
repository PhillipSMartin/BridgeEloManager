## Commands

```bash
# Typecheck everything
pnpm run typecheck

# Build everything (typecheck + all packages)
pnpm run build

# Regenerate API hooks and Zod schemas from OpenAPI spec
pnpm --filter @workspace/api-spec run codegen

# Push DB schema to the database (dev only — no migration files)
pnpm --filter @workspace/db run push

# Run the API server in dev mode (build + start)
pnpm --filter @workspace/api-server run dev

# Run the frontend dev server (requires PORT and BASE_PATH env vars)
PORT=3000 BASE_PATH=/ pnpm --filter @workspace/bridge-elo run dev
```

There are no tests in this project.

## Architecture

pnpm workspace monorepo. Packages use `workspace:*` references; shared catalog versions are in `pnpm-workspace.yaml`.

```
lib/
  db/                  — Drizzle ORM schema, PostgreSQL pool (@workspace/db)
  api-spec/            — OpenAPI spec (openapi.yaml) + Orval codegen config
  api-zod/             — Generated Zod validators for server-side request/response validation
  api-client-react/    — Generated TanStack Query hooks + custom fetch client for the frontend

artifacts/
  api-server/          — Express 5 backend, built with esbuild to CJS
  bridge-elo/          — React + Vite + Tailwind CSS frontend
  mockup-sandbox/      — Standalone sandbox for UI mockups (not part of the main app)
```

### API type-safety pipeline

The single source of truth is `lib/api-spec/openapi.yaml`. Running `codegen` drives Orval to produce:
- `lib/api-client-react/src/generated/` — TanStack Query hooks (split mode, one file per tag)
- `lib/api-zod/src/generated/api.ts` — Zod schemas (single-file mode to avoid duplicate exports)

The frontend imports from `@workspace/api-client-react`; the server imports from `@workspace/api-zod` to validate requests and parse responses. When adding or changing an API endpoint, update `openapi.yaml` first, run `codegen`, then implement in the server route and consume in the frontend.

`lib/api-zod/src/index.ts` only re-exports from `./generated/api` (not `./generated/types`) to avoid duplicate export conflicts between Zod schemas and TypeScript interfaces generated by Orval.

### Database

`lib/db/src/index.ts` initializes a `pg.Pool` from `DATABASE_URL` and creates a Drizzle instance. The server runs `bootstrapDatabase()` at startup (`artifacts/api-server/src/lib/bootstrap.ts`) which issues `CREATE TABLE IF NOT EXISTS` DDL and inline column migrations — there are no migration files. `drizzle-kit push` is used in development to sync schema changes.

### Frontend data flow

`artifacts/bridge-elo/src/hooks/use-bridge.ts` contains the two main hooks (`useBridgeData`, `useTournamentRankingsData`). Components call these hooks and the generated API hooks directly; there is no additional global state layer.

The Rankings tab uses a `/api/all-rankings` endpoint (defined in `artifacts/api-server/src/routes/tournaments.ts`) that is **not** in the OpenAPI spec — it bulk-fetches all tournament rankings in a single query for performance.

### ELO computation

ELO is computed entirely server-side in `artifacts/api-server/src/lib/elo.ts` and served via `GET /api/elo-history`. All players start at 1500. For each tournament round, the algorithm uses `reverseRanking` (0 = last place, higher = better) as the raw score. K-factor is 16.

### Vite dev server

`artifacts/bridge-elo/vite.config.ts` requires `PORT` and `BASE_PATH` environment variables at startup — it will throw if either is missing.
